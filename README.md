# 集成工業プランナー — AIC Layout Planner

『アークナイツ：エンドフィールド』の集成工業を、ブラウザ上で厳密に設計・検証するツール。
目的は「なんとなく置けるツール」ではなく、**台数・面積・電力・搬送本数を数値で詰める**こと。

単一HTMLの試作（JS 2,878行）を、保守できる構成へ作り直している最中です。

- 仕様書: [`HANDOFF.md`](./HANDOFF.md)
- 参照実装（**動く仕様書**。挙動が食い違ったらこちらが正しい）: [`reference/aic-planner.html`](./reference/aic-planner.html)

## 開発

```bash
npm install
npm test        # Vitest
npm run typecheck
npm run dev     # Vite
```

## 画面で気をつけたこと

**視認性**

- 本文13px以上、数値は等幅・桁揃え。前景と背景のコントラストは本文で 7:1 以上
- **色だけに意味を持たせない。**上限に到達したラインは白の破線（品目色に琥珀があるため、
  琥珀の線では区別がつかない）、診断は色に加えて 停止／注意／上限 の文字、
  稼働率はバーと枠色の両方
- **読めない大きさの文字は描かない。**9px を下限にして、入らないときは品目色の点に落とす。
  潰れた文字は情報にならず、線や色の判別を邪魔するだけになる
- 流れていないラインは薄くするだけで品目色は保つ。灰色一色にすると、
  止まっている系統ほど読み解きたいのに何の線か分からなくなる
- ラインは暗い縁取りを敷いてから品目色を重ねる（背景に溶けない）
- **この計画がどれだけ推定値に依存しているか**を検査パネルと生産目標の画面に常に出す（HANDOFF §8-6）

**操作性**

- **取り消し／やり直し**（<kbd>Ctrl+Z</kbd>）。自動配置もデータ編集も戻せる
- ツールは <kbd>1</kbd>〜<kbd>4</kbd>、向きは <kbd>R</kbd>、全体表示は <kbd>F</kbd>、網羅状況は <kbd>V</kbd>
- 設備はドラッグで移動（置ける／置けないを枠色で予告）、空白のドラッグでスクロール、
  ホイールはカーソル位置を軸に拡大縮小
- 盤面の要素にカーソルを合わせると、稼働率や流量が吹き出しで出る
- 診断の行はクリックで該当箇所へジャンプ（キーボードでも操作できる）
- 変更はブラウザに自動保存。未保存の状態はヘッダーに出る
- 失敗は理由まで返す（「搬出口が満杯です。分流器を挟んでください。」）

## 移植の正しさをどう担保しているか

参照実装は「動く仕様書」なので、目視ではなく**機械で突き合わせている**。
`test/helpers/reference.ts` が `reference/aic-planner.html` から計算部分だけを
切り出して Node 上で評価するので、同じ入力を両方に与えて結果を比べられる。

- seed データ … JSON がキー順まで完全一致
- ポート幾何 … 初期データ全40設備 × 4向き
- 経路探索 … ランダム盤面60通り・500回以上の接続で、選ばれた口と経路が一致
- ソルバー … ランダム盤面40通りで稼働率・流量・電力・倉庫収支・診断の文言まで一致
- 逆算 … 20通りの目標で台数・原料・面積・電力・提案値が一致
- 自動配置 … 13通り×2方式で、設備・ラインの経路・盤面サイズ・ソルバー結果まで一致
- 保存形式 … 現行アプリが書き出した設計図を読み、書き戻すと1文字も違わない
- まとめて入力 … 書き出し文字列と読み込み結果が一致。往復してもレシピ数が変わらない

### 守っている境界

- `domain/` は `window` / `document` / `canvas` を参照しない。
- 参照実装の `D.nodes` のようなグローバル可変状態は持ち込まない。
  可変だった `PIPE_CAP` は `GameConfig` として明示的に持ち回る。
- 保存 JSON は現行ファイルがそのまま読めること（後方互換）。
  `test/fixtures/reference-save.json` が現行アプリの書き出し形。
